# Rabin Assistant

پنل سبک فارسی برای تعریف و زمان‌بندی سفارش‌های خرید و فروش، با Go و با Go و بدون نیاز به دانلود وابستگی بیرونی برای تقویم.

## نصب یک‌خطی روی Ubuntu

مخزن در زمان نصب باید Public باشد. با کاربر root فقط این یک خط را روی سرور اجرا کنید:

```bash
bash -c "$(curl -fsSL https://raw.githubusercontent.com/hatinati2/rabin-assistant/main/install-public.sh)"
```

نصب‌کننده سورس را دریافت می‌کند، در صورت نیاز Go را نصب می‌کند، برنامه را کامپایل و سرویس systemd را راه‌اندازی می‌کند. روی نصب قبلی، تنظیمات موجود و سفارش‌های ذخیره‌شده حفظ می‌شوند؛ آدرس پیش‌فرض قبلی `127.0.0.1:8098` نیز به `0.0.0.0:8098` تغییر می‌کند.

## ورود به پنل

در مرورگر باز کنید:

`http://SERVER_IP:8098`

نام کاربری و رمز اولیه:
```bash
cat /root/rabin-assistant-credentials.txt
```

## مدیریت سرویس

```bash
systemctl status rabin-assistant
journalctl -u rabin-assistant -f
systemctl restart rabin-assistant
```

## تنظیمات

فایل محیطی: `/etc/rabin-assistant.env`

- `RABIN_ADMIN_USER`
- `RABIN_ADMIN_PASS`
- `RABIN_ADDR` (پیش‌فرض `0.0.0.0:8098`)
- `RABIN_DATA_DIR` (پیش‌فرض `/var/lib/rabin-assistant`)

نصب‌کننده منطقه زمانی خود سرور را روی `Asia/Tehran` تنظیم می‌کند. نمایش ساعت، ثبت زمان سفارش و زمان‌بندی همگی بر اساس ساعت ایران هستند.

## دو مسیر اجرای سفارش

هر سفارش یک مسیر اجرا دارد و این مقدار همراه سفارش ذخیره می‌شود:

- **بدون API (فعال):** سفارش در پنل زمان‌بندی می‌شود. پس از رسیدن موعد، وضعیت آن به «آماده بررسی» تغییر می‌کند و در تاریخچه می‌آید. کاربر سفارش را شخصاً در سامانه رابین وارد می‌کند و سپس می‌تواند دکمه «ثبت دستی انجام شد» را بزند تا تأیید دستی آن در تاریخچه ثبت شود. این دکمه فقط تأیید کاربر را ذخیره می‌کند و موفقیت سفارش را از کارگزاری استعلام نمی‌کند.
- **با API (مسیر ارسال عادی):** زمان‌بند پس از سررسید، سفارش را با یک درخواست به مسیر عادی `POST /api/order` رابین می‌فرستد؛ این مسیر از «پیش‌سفارش» استفاده نمی‌کند. سفارش API باید ISIN دوازده‌کاراکتری داشته باشد. این مسیر به‌طور پیش‌فرض خاموش است و فقط با فعال‌سازی صریح `RABIN_ENABLE_LIVE_ORDER_SUBMISSION=true` قابل انتخاب می‌شود. مقادیر enum از بستهٔ عمومی فرانت‌اند رابین استخراج شده‌اند: خرید `1` و فروش `2`.

## تنظیمات اتصال به حساب رابین

از منوی «اتصال به رابین» می‌توان نام کاربری و رمز عبور حساب رابین را ذخیره یا حذف کرد. رمز عبور در فایل داده به‌صورت متن ساده نگهداری نمی‌شود؛ با AES-256-GCM رمز می‌شود و کلید جداگانه در `/etc/rabin-assistant.key` با دسترسی محدود برای کاربر سرویس قرار می‌گیرد. فایل رمزنگاری‌شده در مسیر داده برنامه با مجوز محدود ذخیره می‌شود. نصب‌کننده در به‌روزرسانی، کلید موجود را حفظ می‌کند و فقط در نصب اولیه آن را می‌سازد.

در صفحه «اتصال به رابین»، دکمه «تست ورود» ورود عادی با نام کاربری و رمز ذخیره‌شده را از سرور انجام می‌دهد. در صورت موفقیت، توکن نشست دریافتی با همان کلید و الگوریتم AES-256-GCM، اما در فایل جداگانه `rabin-session.enc.json` ذخیره می‌شود؛ زمان آخرین ورود موفق نیز در پنل نمایش داده می‌شود. در صورت رد شدن ورود، پیام برگشتی رابین در پنل نشان داده می‌شود. این صفحه فقط ورود و دریافت نشست را آزمایش می‌کند و خودش سفارشی نمی‌فرستد. با تغییر یا حذف اطلاعات ورود، نشست قبلی نیز پاک می‌شود. ارسال سفارش فقط از زمان‌بند، در مسیر API و پس از فعال‌سازی صریح انجام می‌شود. اگر کلید رمزنگاری حذف یا جایگزین شود، اطلاعات ذخیره‌شده قابل رمزگشایی نخواهند بود؛ بنابراین از فایل کلید محافظت کنید و آن را همراه نسخه پشتیبان امن نگه دارید.

## وضعیت نسخه فعلی

انتخاب تاریخ در پنل با تقویم گرافیکی شمسی انجام می‌شود (ماه قبل/بعد و انتخاب روز). همچنین کادر تاریخ قابل تایپ دستی است؛ تاریخ را مثل `۱۴۰۵/۰۸/۱۴` وارد کنید و ساعت را در فیلد جداگانه با دقت میلی‌ثانیه انتخاب کنید. ارقام فارسی و عربی در ورودی متنی سازگار نیز پذیرفته می‌شوند. زمان‌سنج داخلی هر ۱۰۰ میلی‌ثانیه موعدها را بررسی می‌کند. کد تقویم شمسی به‌صورت محلی در پوشه `internal/jalaali` قرار دارد و نصب برای این بخش به اینترنت یا Go module proxy نیاز ندارد. سفارش‌ها در فایل JSON محلی ذخیره می‌شوند. مسیر بدون API یک گردش‌کار ثبت دستی و تأیید کاربر است. مسیر API دارای کلاینت ارسال و وضعیت‌های جداگانه «در حال ارسال»، «ثبت در رابین»، «ارسال ناموفق» و «نتیجه نامشخص» است. قبل از هر درخواست، وضعیت `submitting` روی دیسک ثبت می‌شود؛ اگر پاسخ قطعی نرسد یا سرویس هنگام ارسال متوقف شود، سفارش خودکار دوباره فرستاده نمی‌شود. فعال‌سازی واقعی همچنان به کد enum خرید/فروش تأییدشده و تنظیم صریح متغیرهای سرور وابسته است.

## نکات

- فایل داده و تنظیمات روی سرور نگهداری می‌شوند و وارد Git نمی‌شوند.
- برای نصب از مخزن خصوصی، نصب‌کننده باید با روش احراز هویت GitHub سازگار شود.
- برای استفاده از مخزن عمومی، تمام سورس کد قابل مشاهده و کپی است.


## آماده‌سازی مرورگر سمت سرور (مرحله بررسی)

برای بررسی اولیه امکان اجرای Chromium روی سرور و دسترسی آن به صفحه ورود رابین، آماده‌ساز زیر اضافه شده است:

```bash
bash -c "$(curl -fsSL https://raw.githubusercontent.com/hatinati2/rabin-assistant/main/deploy/prepare-browser.sh)"
```

سپس دستور آزمایشی چاپ‌شده را اجرا کنید. این بررسی فقط صفحه عمومی/ورود را می‌خواند و مشخصات فیلدهای قابل مشاهده را گزارش می‌کند؛ **وارد حساب نمی‌شود، سفارشی ثبت نمی‌کند و اتصال اجرای خودکار سفارش هنوز پیاده‌سازی یا فعال نشده است.** پس از تأیید دسترسی شبکه و شناسایی فرم واقعی، می‌توان مرحله ورود امن و سپس اجرای سفارش را جداگانه پیاده‌سازی و آزمایش کرد.
